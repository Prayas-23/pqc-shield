# PQ-DRIFTLAB lab: safety rules

The lab produces real TLS 1.3 handshake captures between containers **we own**, on this machine only.
These rules apply to everything under `lab/`, to `docker-compose.yml`, and to any script that drives them.
They restate rule 4 of `AGENTS.md`; if a task seems to need an exception, stop and ask instead.

## Rules

1. **One internal network.** Every container sits on a single Docker network declared with
   `internal: true`. The lab has no route to the internet, the LAN, or the host's other networks.
   Nothing in the compose file may publish ports to the host, use `network_mode: host`, or attach
   a container to a second, non-internal network.
2. **Attack-like traffic stays between our own containers.** Anything that resembles an attack
   (floods, malformed handshakes, anomalous clients) is sent only from one lab container to
   another lab container, over that internal network. Defensive purpose only: the traffic exists to
   study detectors, and no exploit code is written or used.
3. **No scanning of any other host.** No port scans, sweeps, or probes of anything outside the lab
   containers. Targets are always lab service names on the internal network, never addresses typed
   in from elsewhere.
4. **No decryption of traffic.** Captures are analysed only through what is visible on the wire
   (handshake sizes, counts, timing, flags). No key logging (`SSLKEYLOGFILE`), no private-key
   export to a decryptor, no TLS interception or MITM.
5. **Captures stay local.** Packet captures are written to `data/pcaps/` only. That path is
   git-ignored (`data/` and `*.pcap`) and is never committed, uploaded, or attached to anything.
6. **Private test PKI only.** Certificates and keys are generated by `lab/gen_certs.sh` for this lab
   (a private CA that nothing outside the lab trusts). They are never installed into a system or
   browser trust store and never reused elsewhere. Generated keys live under `lab/` build output
   or a Docker volume and are git-ignored.
7. **Nothing external is pulled at run time.** Build inputs (base image, OpenSSL source tarball) are
   downloaded at build time and verified by checksum. Running containers make no outbound calls.
8. **Real or absent.** A handshake profile that the toolchain does not truly support is dropped and
   reported as FAIL. It is never faked, simulated, or silently replaced by a default group or
   signature algorithm. Captures are labelled with the profile that was actually negotiated.
9. **Tear down when done.** `docker compose down -v` removes the containers, network and volumes.
   Captures in `data/pcaps/` are kept until the user deletes them.

## What the lab is for

TLS 1.3 over TCP handshakes for the profiles in `pqdl.profiles`, with the chain length (`n_certs`)
set explicitly by us, so the size model can be tested instead of fitted. The captures feed the
`pcap.py` / `features.py` pipeline, one dataset `source` per capture campaign (never merged with
CIC-IDS2017 or CIC-PQC_OAV).

## Session tickets are disabled

`s_server` runs with `-no_ticket -num_tickets 0` by default (env `TICKETS=1` turns them back on; the default
is `TICKETS=0`). By default OpenSSL sends two `NewSessionTicket` messages after every TLS 1.3 handshake. They
add server-to-client bytes that are not part of the handshake we are measuring, and they would change the
byte counts and packet patterns of every connection in the same way for all profiles, which blurs the size
model comparison. Disabling them keeps the post-handshake traffic limited to the workload itself.

## Workloads and the capture matrix

`lab/workloads/` holds three workloads (`benign_web`, `handshake_flood`, `slow_send`), identical for every
crypto profile (same scripts, same seed, same request sequence). Each has hard caps (<= 1000 sessions,
<= 600 s; the flood is also capped at 20 connections/s and 4 concurrent). `lab/run_matrix.sh` drives them
and writes `data/pcaps/<kem>_<auth>_<chain>_<workload>.pcap` plus `data/pcaps/manifest.csv`.
The capture sidecar writes its pcap inside its own container and `run_matrix.sh` copies it out after tcpdump
exits, then refuses the capture if tcpdump reports any dropped packets (writing per packet to a Windows bind
mount made the kernel drop packets in the first mini-run).
The server serves files with `s_server -WWW` from `/srv/www` (1 KB, 10 KB, 100 KB, 500 KB, fixed content).

## Status

Part B done: OpenSSL 3.5.9 image, private test PKI, smoke test, internal-network compose file.

- Build: `docker build --target lab -t pqdl-lab:openssl-3.5.9 lab/` (verifies the source tarball's SHA-256).
- Smoke test: `docker run --rm pqdl-lab:openssl-3.5.9 /lab/smoke_test.sh` (exit 1 if any profile fails).
- Compose: `KEM=mlkem768 AUTH=mldsa44 CHAIN=leaf_int docker compose up -d server capture`, then
  `docker compose run --rm client`, then `docker compose down -v`.
- **SLH-DSA is not supported in TLS 1.3 by this OpenSSL build** and is dropped from the matrix
  (details and exact error text in `docs/lab_findings.md`). `mldsa87` was added in its place.
- Windows note: when calling `docker` from Git Bash, set `MSYS_NO_PATHCONV=1` or paths like `/lab/x.sh`
  get rewritten.
