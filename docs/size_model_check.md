## 5. What the table supports, and what it does not

### Supported by the table (computed)

- Client key share: `e2_client_size` equals the model client share in every row of every cell: **True**.
- Client record offset: `e2_client_record_len - e2_client_size` equals 255 (ClientHello base + record header) in every row of every cell: **False** (residuals in section 3).
- Server side, `e2c_total_bytes`: **consistent across cells with n_certs = 1** (solved range 0.94 to 1.03); differences only, n_certs fitted.
- Server side residuals at each n_certs in {1, 2, 3}, in sections 4a and 4b.

### Not supported

- **Absolute sizes.** The meaning of `e2c_total_bytes` in the dataset is not documented in the files we have, so only differences between cells are compared, never absolute values. Quote any result here as "differences only, n_certs fitted".
- **`e2_server_record_len`.** Not compared (see section 4); the table in section 1 is the only place it appears.
- **A specific n_certs.** n_certs is the only free parameter, so it absorbs any other model error (wrong certificate encoding, extra extensions, compression). A solved n_certs that looks plausible does not confirm the model; consistency across cells is the only evidence, and it is limited to the cells listed.
- **RSA cells.** Cells with `auth=rsa` are not compared (size unknown, see section 2).
- **Standard sizes.** Every number in SIZES is marked VERIFY and has not been checked against the standards.
- **Per-row variation.** The model is deterministic; observed values vary row to row (see section 1), so deltas of means are compared and the spread is not modelled.
- **Transport effects.** TCP/IP headers, TLS record overhead per fragment, retransmissions and handshake compression are not modelled; if they differ between cells they appear as residuals.
- **Anything about real networks.** CIC-PQC_OAV is a synthetic container testbed.
