# Replicate-capture timing analysis (PCAP level)

Generated by `scripts/rep_timing.py`; every number below is computed from `data/flows/lab_flows_rep.csv` and the main-run `data/flows/lab_flows.csv`. Tables: `results/rep_timing.csv`, `results/rep_timing_range.csv`, `results/rep_timing_runorder.csv`.

## Method

- Unit = pcap; statistic = median of the feature over the pcap's connections. 4 profiles (all leaf_int) x 4 pcaps (replicates 1-3 + the main-run pcap as replicate 0, flagged `main run`) per workload.
- Variance components: balanced one-way random-effects ANOVA. ICC = var_between / (var_between + var_within); var_within is pcap-to-pcap noise inside one profile. 95% CI: percentile bootstrap, pcaps resampled within profile (5000 draws, seed 20261125).
- Permutation test: profile labels shuffled across the 16 pcaps within each workload (10000 permutations, seed fixed), statistic = one-way F of pcap medians. Holm correction across the 6 features within a workload.
- Sensitivity `rep3`: the same ICC and test using replicates 1-3 only (main run excluded, since it was captured at a different time, in profile-grouped order, with the code commit not recorded).
- Run order: Spearman of run_order vs pcap median over the 12 replicate pcaps per workload; the `profile_centred` version subtracts each profile's mean first so profile effects cannot masquerade as drift. The main run has no run_order in the same sequence, so it is excluded.

## Caveats

- Only 4 profiles, 3 replicates plus one main-run pcap each: 4 pcaps per profile gives very wide ICC CIs; the bootstrap resamples only 4 values per profile.
- Local Docker network on one laptop, one machine, one day: timings do not transfer to real networks.
- The 4 features of a workload are strongly correlated, so Holm over 6 features is conservative and the 'number of significant features' is not a count of independent findings.
- Replicates within a replicate round share the workload seed across profiles (seed 1234 + replicate), so replicate effects are partly shared by design; the random capture order breaks time-confounding only in expectation, with one order seed.
- A significant profile effect shows the profiles differ in timing; it does not by itself show the cause is the cryptography (larger handshakes also change packet counts and flow duration mechanically).
- hs_* features measure the handshake phase and are mechanically linked to handshake size; app_* features should not be if the phase split is clean.
