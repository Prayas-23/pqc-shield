# Detector baseline notes

Generated by `scripts/detector_baseline.py`; every number below is computed from the flows CSVs. Full results: `results/detector_baseline.csv`, `results/detector_baseline_dose_response.csv`, `results/detector_baseline_confirmation.csv`.

## Scope and labels

- **The attacks are scripted attack-like workloads, not real attacks.** benign = benign_web + benign_api; attack = handshake_flood (many short TLS handshakes) + slow_send (slow trickle of data), generated between our own local containers.
- Data: `data/flows/lab_flows.csv` (source `pq_lab`, main run, 18 profiles) for all training and evaluation. `lab_flows_rep.csv` is only scored by the already-trained naive detectors (confirmation); no dataset is ever merged into a training set.

## Splits

- Time-blocked inside every pcap (profile x workload): flows sorted by capture order (`conn_index`); first 40% train, next 20% validation, last 40% test. Sizes per pcap: 300 -> 120/60/120, 200 -> 80/40/80, 50 -> 20/10/20.
- All methods are evaluated on the SAME test block of each profile. Nothing is tuned on test.

## Feature views (explicit lists, asserted in code)

- V_FLOW = LAB_FLOW_FEATURES (11 whole-connection flow features, what an off-the-shelf flow detector sees). V_APP = LAB_APP_FEATURES (32 application-phase features; handshake removed, needs TLS parsing). Missing packet-size slots (flow shorter than k packets) are filled with 0.
- `hs_*` and every `LAB_EXCLUDED` column are rejected by `assert_clean_features`. `hs_s2c_bytes` appears only in the dose-response table as a descriptive x-axis.

## Detectors and operating point

- RandomForest (100 trees, supervised, score = P(attack)); autoencoder (sklearn MLPRegressor (16, 4, 16), benign-only, score = reconstruction MSE on standardised features); IsolationForest (100 trees, benign-only). Model seeds 11, 12, 13, 14, 15 (5 repeats); values are means over seeds, `seed_sd` is the spread across seeds.
- Threshold = 95th percentile of the BENIGN VALIDATION scores of the training domain (design FPR 5%); flag if score > threshold. RF scores tie (many exact 0s), so its in-domain FPR can sit below 5%.
- 95% CIs: 1000 seeded bootstrap resamples of test flows (stratified: benign, each attack type), same resampled flows for every model seed; the CI is for the seed-mean and does not include model-seed or pcap-level (batch) variance.
- AE fits that stopped at max_iter=2000 without converging: 0 of 105.

## Methods

1. naive: train + threshold on the classical profile (X25519|ecdsa_p256, leaf_int) only, V_FLOW. 2. oracle: train + threshold on the target profile's own train/val blocks. 3. pooled: train on the union of all 18 profiles' train blocks, threshold on the union of validation blocks. 4. naive_app: as naive but on V_APP.

## Caveats

- Scripted workloads, not real attacks; benign traffic is two scripted client behaviours.
- One machine, local Docker network, one TLS cipher suite; timing features inherit all lab-noise caveats from `docs/rep_timing_notes.md`.
- Time-blocked splits within one pcap per (profile, workload): train and test come from the same capture session, so pcap-level effects are shared by the splits and no cross-capture generalisation is tested (except the replicate confirmation).
- Handshake feature values are constant (or nearly) within a profile, so a profile's whole shift is one value; 18 profiles are 18 'doses', not 18 independent samples of traffic.
- Bootstrap CIs resample flows as if independent; flows within a pcap are not exactly independent, so the intervals are optimistic.
- Per-attack-type TPR for slow_send rests on 20 test flows per profile.
